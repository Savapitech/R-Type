# RFC — R-Type Network Protocol

Version: 0.1
Transport: UDP
Architecture: Authoritative server

## 1. Conventions

Integers are encoded in big-endian.

Positions and rotations use 32-bit IEEE-754 numbers.

Types used:

| Name | Size |
|---|---:|
| `uint8` | 1 byte |
| `uint16` | 2 bytes |
| `uint32` | 4 bytes |
| `uint64` | 8 bytes |
| `float32` | 4 bytes |

The client can never directly create, move, or delete a network entity.

## 2. Command Types

```cpp
enum class CommandType : std::uint8_t
{
    Connect = 0x01,
    Input = 0x02,
    Ping = 0x03,
    Disconnect = 0x04,

    Welcome = 0x81,
    ConnectionRejected = 0x82,
    Snapshot = 0x83,
    CreateEntity = 0x84,
    DestroyEntity = 0x85,
    Pong = 0x86
};
```

Commands `0x01` to `0x7F` are sent by the client.

Commands `0x81` to `0xFF` are sent by the server.

## 3. Client to Server Commands

### 3.1 Connect

Requests a connection to the server.

Payload:

| Field | Type | Description |
|---|---|---|
| `protocolVersion` | `uint16` | Protocol version |
| `clientNonce` | `uint64` | Random value generated by the client |

The client resends this command as long as it has not received `Welcome` or `ConnectionRejected`.

The server must process multiple requests with the same `clientNonce` as a single connection.

### 3.2 Input

Transmits the current intentions of the player.

Payload:

| Field | Type | Description |
|---|---|---|
| `inputSequence` | `uint32` | Increasing input number |
| `clientTick` | `uint32` | Client local tick |
| `actions` | `uint8` | Actions bitmask |

Actions:

```cpp
enum class InputAction : std::uint8_t
{
    None = 0x00,
    Up = 0x01,
    Down = 0x02,
    Left = 0x04,
    Right = 0x08,
    Shoot = 0x10
};
```

Multiple actions can be combined.

Example:

```text
Up + Right + Shoot = 0x19
```

The client also sends `None` when no key is pressed.

The server ignores inputs with a sequence older than the last processed input.

`Shoot` is an action. The client never creates the projectile itself.

### 3.3 Ping

Measures the RTT.

Payload:

| Field | Type | Description |
|---|---|---|
| `timestamp` | `uint64` | Timestamp generated by the client |

The server responds with a `Pong` containing the same timestamp.

### 3.4 Disconnect

Informs the server that the client is voluntarily leaving the game.

Payload:

| Field | Type | Description |
|---|---|---|
| `reason` | `uint8` | Disconnection reason |

```cpp
enum class DisconnectReason : std::uint8_t
{
    ClientQuit = 0x01,
    Timeout = 0x02,
    ProtocolError = 0x03,
    ServerShutdown = 0x04
};
```

The server must not rely solely on this command, as a UDP packet can be lost. It must also have a timeout.

## 4. Server to Client Commands

### 4.1 Welcome

Accepts the client connection.

Payload:

| Field | Type | Description |
|---|---|---|
| `clientId` | `uint32` | Client identifier |
| `playerNetworkId` | `uint32` | Player Network ID |
| `serverTick` | `uint32` | Current server tick |

The server is the only one to assign Network IDs.

### 4.2 ConnectionRejected

Rejects the connection.

Payload:

| Field | Type | Description |
|---|---|---|
| `reason` | `uint8` | Rejection reason |

```cpp
enum class RejectionReason : std::uint8_t
{
    ServerFull = 0x01,
    InvalidProtocolVersion = 0x02,
    InvalidPacket = 0x03
};
```

### 4.3 CreateEntity

Requests the client to create a local representation of a server entity.

Payload:

| Field | Type | Description |
|---|---|---|
| `serverTick` | `uint32` | Creation tick |
| `networkId` | `uint32` | Network identifier |
| `entityType` | `uint8` | Entity type |
| `positionX` | `float32` | Horizontal position |
| `positionY` | `float32` | Vertical position |
| `rotation` | `float32` | Rotation |

```cpp
enum class EntityType : std::uint8_t
{
    Player = 0x01,
    Enemy = 0x02,
    PlayerProjectile = 0x03,
    EnemyProjectile = 0x04
};
```

The client associates the Network ID with a local ECS entity.

```cpp
std::unordered_map<std::uint32_t, rtk::ecs::Entity> networkEntities;
```

If the Network ID already exists, the client does not create a second entity.

Textures and graphical resources are never sent by the server. The client chooses them based on `entityType`.

### 4.4 Snapshot

Transmits the complete state of network entities at a given tick.

Payload:

| Field | Type | Description |
|---|---|---|
| `serverTick` | `uint32` | Snapshot tick |
| `entityCount` | `uint16` | Number of entities |
| `entities` | `EntityState[]` | Entity states |

Each `EntityState` contains:

| Field | Type | Description |
|---|---|---|
| `networkId` | `uint32` | Network identifier |
| `entityType` | `uint8` | Entity type |
| `positionX` | `float32` | Horizontal position |
| `positionY` | `float32` | Vertical position |
| `rotation` | `float32` | Rotation |

In version 0.1, a snapshot contains all existing network entities.

If the client receives an unknown Network ID in a snapshot, it can create the entity using `entityType`.

If a more recent snapshot has already been processed, the client ignores older snapshots.

### 4.5 DestroyEntity

Requests the client to delete a local entity.

Payload:

| Field | Type | Description |
|---|---|---|
| `serverTick` | `uint32` | Destruction tick |
| `networkId` | `uint32` | Entity to delete |
| `reason` | `uint8` | Deletion reason |

```cpp
enum class DestroyReason : std::uint8_t
{
    Unknown = 0x00,
    Collision = 0x01,
    OutOfBounds = 0x02,
    PlayerDisconnected = 0x03,
    GameEnded = 0x04
};
```

Only the server can send `DestroyEntity`.

If the Network ID does not exist locally, the client ignores the command.

### 4.6 Pong

Responds to a `Ping` command.

Payload:

| Field | Type | Description |
|---|---|---|
| `timestamp` | `uint64` | Timestamp received in the Ping |

The client calculates the RTT:

```text
RTT = current time - timestamp
```

## 5. Frequencies

| Command | Frequency |
|---|---:|
| `Input` | 20 times per second |
| `Snapshot` | 20 times per second |
| `Ping` | 1 time per second |
| `CreateEntity` | On creation |
| `DestroyEntity` | On destruction |

## 6. Authority Rules

The client can only send:

```text
Connect
Input
Ping
Disconnect
```

The server can only send:

```text
Welcome
ConnectionRejected
Snapshot
CreateEntity
DestroyEntity
Pong
Disconnect
```

A server receiving `CreateEntity`, `Snapshot` or `DestroyEntity` from a client must ignore the packet.

A client receiving these commands from an address other than the server's must ignore the packet.

## 7. Session Flow

```text
1. Client -> Connect
2. Server -> Welcome
3. Server -> CreateEntity of the player
4. Client -> Input
5. Server -> Snapshot
6. Client -> Input with Shoot
7. Server creates the projectile
8. Server -> CreateEntity of the projectile
9. Server -> Snapshot
10. Server detects a collision
11. Server -> DestroyEntity
12. Client -> Disconnect
```
